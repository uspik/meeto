# Meeto — контекст проекта

Телеграм-бот для организации мероприятий. Весь основной интерфейс живёт
в mini-app, бот отвечает за вход и быстрые ответы из чата.

Домен: `app.kroll1.ru`. Общение с автором проекта — по-русски.

## Где что лежит

```
SPEC.md                      продуктовая спецификация: роли, права, жизненный
                             цикл мероприятия, кворум, уведомления
schema.sql                   эталонная схема PostgreSQL (не применяется напрямую,
                             модели SQLAlchemy — источник правды)
calendar-prototype.html      исходный HTML-прототип, визуальный эталон вёрстки
app/backend/                 FastAPI + SQLAlchemy 2.0 async + aiogram
  app/api/                   auth, calendar, events, groups, me, users
  app/services/              events (RSVP, очередь, кворум), invites, notify
  app/models.py              модели — источник правды по схеме
  app/migrate.py             добавление недостающих колонок до появления Alembic
  tests/smoke.py             сквозной сценарий на SQLite, 93 проверки
app/miniapp/                 React 18 + TypeScript + Vite 6
  src/views/                 MonthView, DayView, ListView, GroupsView,
                             EventSheet, WhoIsGoing, Wizard
  src/components/            EventRow, Icon, StatusChip, Select, Overlay,
                             PeoplePicker, Pickers, BottomBar, Skeleton
  src/styles.css             весь CSS одним файлом, перенесён из прототипа
app/docker-compose.yml       db, redis, api, bot, worker, miniapp, nginx, certbot
app/DEPLOY.md                развёртывание с нуля + приложения для nginx и Caddy
```

## Команды

```bash
# бэкенд (из app/backend, venv с requirements.txt)
python -m tests.smoke          # сквозной прогон, должен быть 0 fail

# фронтенд (из app/miniapp)
npx tsc --noEmit
npx vite build

# сервер
cd ~/meeto && git pull
cd app && docker compose build && docker compose up -d
```

`api`, `bot` и `worker` используют один образ `meeto-backend:local` —
пересобирать нужно все три, `docker compose build` без аргументов это делает.

## Что важно помнить

**Схема меняется через `app/migrate.py`.** Alembic не подключён, а
`create_all` добавляет только недостающие таблицы, не колонки. Новую колонку
в живую таблицу надо описать в `ADDITIONS` — `init_db()` доложит её при старте.
По той же причине новые enum'ы в существующих таблицах объявляются как
`String(16)`, а не как нативный тип БД.

**Уведомления о правках — только по значимым полям.** Сравниваются старое и
новое значения (`really_changed & SIGNIFICANT`), потому что форма всегда шлёт
все поля целиком. Уведомляются только те, кто идёт, стоит в очереди или под
вопросом. Отдельных уведомлений о каждом чужом ответе нет — это отдельно
отменялось как шумное.

**Время рендерится в часовом поясе получателя.** `notify.render()` берёт
`when_ts` в UTC и переводит через `zoneinfo` по `user.timezone`. Шаблон
подставляется через `_Blank`, чтобы отсутствующее поле не ломало сообщение
сырыми скобками.

**RSVP всегда под `SELECT ... FOR UPDATE` по строке мероприятия** — иначе
одновременные ответы дают овербукинг. Это касается и API, и обработчика
inline-кнопок в боте.

**Анимации появления делаются на `@keyframes`, а не на переходах классов** —
переключение класса после монтирования в React срабатывает ненадёжно.
Для смены вкладок используется двухслойный кроссфейд: снимок уходящего экрана
живёт 340 мс. `will-change: transform` на `.view` ставить нельзя — он ловит
`position: fixed` у шторок, и они обрезаются шапкой. Шторки и выпадающие
списки рисуются через портал (`Overlay.tsx`).

**CSS один на всё приложение, имена классов легко сталкиваются.** Уже ловили
три таких бага (`.now`, `.sel`, `.dots`). Новый класс лучше проверять поиском
по `styles.css`.

## Правила работы, о которых просил автор

- Не говорить «готово», пока правки не собраны и не закоммичены. Дважды
  случалось, что на устройство ехала старая сборка, а изменения оставались
  в рабочей копии. В интерфейс добавлен видимый штамп сборки (`__BUILD__`)
  и `no-store` на `index.html` — по ним видно, свежая ли версия приехала.
- Убирать за собой `.git/index.lock` после git-команд из песочницы —
  иначе у автора не выполняется `git add`.
- Комментарии в коде — по-русски, объясняют «почему», а не «что».
