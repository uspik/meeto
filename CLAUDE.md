# Meeto — контекст проекта

Телеграм-бот для организации мероприятий. Весь основной интерфейс живёт
в mini-app, бот отвечает за вход и быстрые ответы из чата.

Домен: `app.kroll1.ru`. Общение с автором проекта — по-русски.

## Где что лежит

```
SPEC.md                      продуктовая спецификация: роли, права, жизненный
                             цикл мероприятия, кворум, уведомления
schema.sql                   эталонная схема PostgreSQL (не применяется напрямую,
                             модели SQLAlchemy — источник правды)
calendar-prototype.html      исходный HTML-прототип, визуальный эталон вёрстки
app/backend/                 FastAPI + SQLAlchemy 2.0 async + aiogram
  app/api/                   auth, calendar, events, groups, me, users
  app/services/              events (RSVP, очередь, кворум), invites, notify
  app/models.py              модели — источник правды по схеме
  app/migrate.py             добавление недостающих колонок до появления Alembic
  tests/smoke.py             сквозной сценарий на SQLite, 93 проверки
app/miniapp/                 React 18 + TypeScript + Vite 6
  src/views/                 MonthView, DayView, ListView, GroupsView,
                             EventSheet, WhoIsGoing, Wizard
  src/components/            EventRow, Icon, StatusChip, Select, Overlay,
                             PeoplePicker, Pickers, BottomBar, Skeleton
  src/styles.css             весь CSS одним файлом, перенесён из прототипа
app/docker-compose.yml       db, redis, api, bot, worker, miniapp, nginx, certbot
app/DEPLOY.md                развёртывание с нуля + приложения для nginx и Caddy
```

## Команды

```bash
# бэкенд (из app/backend, venv с requirements.txt)
python -m tests.smoke          # сквозной прогон, должен быть 0 fail

# фронтенд (из app/miniapp)
npx tsc --noEmit
npx vite build

# сервер
cd ~/meeto && git pull
cd app && docker compose build && docker compose up -d
```

`api`, `bot` и `worker` используют один образ `meeto-backend:local` —
пересобирать нужно все три, `docker compose build` без аргументов это делает.

## Что важно помнить

**Схема меняется через `app/migrate.py`.** Alembic не подключён, а
`create_all` добавляет только недостающие таблицы, не колонки. Новую колонку
в живую таблицу надо описать в `ADDITIONS` — `init_db()` доложит её при старте.
По той же причине новые enum'ы в существующих таблицах объявляются как
`String(16)`, а не как нативный тип БД.

**Уведомления о правках — только по значимым полям.** Сравниваются старое и
новое значения (`really_changed & SIGNIFICANT`), потому что форма всегда шлёт
все поля целиком. Уведомляются только те, кто идёт, стоит в очереди или под
вопросом. Отдельных уведомлений о каждом чужом ответе нет — это отдельно
отменялось как шумное.

**Время рендерится в часовом поясе получателя.** `notify.render()` берёт
`when_ts` в UTC и переводит через `zoneinfo` по `user.timezone`. Шаблон
подставляется через `_Blank`, чтобы отсутствующее поле не ломало сообщение
сырыми скобками.

**RSVP всегда под `SELECT ... FOR UPDATE` по строке мероприятия** — иначе
одновременные ответы дают овербукинг. Это касается и API, и обработчика
inline-кнопок в боте.

**Анимации появления делаются на `@keyframes`, а не на переходах классов** —
переключение класса после монтирования в React срабатывает ненадёжно.
Для смены вкладок используется двухслойный кроссфейд: снимок уходящего экрана
живёт 340 мс. `will-change: transform` на `.view` ставить нельзя — он ловит
`position: fixed` у шторок, и они обрезаются шапкой. Шторки и выпадающие
списки рисуются через портал (`Overlay.tsx`).

**CSS один на всё приложение, имена классов легко сталкиваются.** Уже ловили
три таких бага (`.now`, `.sel`, `.dots`). Новый класс лучше проверять поиском
по `styles.css`.

**`dedup_key` в аутбоксе живёт до отправки, а не вечно.** Ключ вида
`invited:{event}:{user}` защищает от двойной отправки одного и того же,
но раньше он навсегда занимал уникальный индекс — и повторное приглашение
(человека убрали и зовут обратно) роняло весь запрос на UNIQUE. Теперь
`enqueue()` пропускает постановку, пока старое уведомление ещё в очереди,
и освобождает ключ, как только оно ушло.

**Список участников чата Telegram боту недоступен.** Bot API отдаёт только
администраторов (`getChatAdministrators`) и число участников — метода «дай
всех» нет ни при каких правах. Поэтому группа из чата заводится на владельце
чата, а остальные попадают в неё кнопкой «Я в деле» под приветствием бота или
ответом на анонс мероприятия. Вся работа с чатом лежит в `services/chats.py`
без aiogram — чтобы её покрывал смоук; `bot.py` только разбирает обновления.

**В групповых чатах нельзя слать кнопку `web_app`** — Telegram отвечает
`BUTTON_TYPE_INVALID`. Наружу из чата ведёт обычная ссылка
`https://t.me/<bot>?startapp` (`kb_for()` выбирает нужный вариант). И ответ
на анонс в чате не убирает клавиатуру: сообщение общее, после первого «иду»
остальные должны сохранить возможность ответить — обновляется только счётчик.

**Уведомление знает адрес: `outbox.chat_id`.** Пусто — письмо в личку
`user_id`, заполнено — сообщение в чат группы, и тогда `user_id` значит лишь
«от кого». Пояс у чата берётся от мероприятия (`payload["tz"]`), а тексты для
чата лежат в `CHAT_TEMPLATES`. Развилку делает `notify.announce()`: в чат
уходят анонс, правка, отмена, напоминание и провал кворума, в личку остаются
адресные — про очередь, места, набранный кворум и исключение.

**По шине едет адрес изменения, а не данные.** `services/bus.py` — Redis
pub/sub, публикуют все три процесса (api, bot, worker), слушает SSE-ручка
`/api/v1/stream`. Клиент получает `{kind, event_id, group_id}` и
перезапрашивает то, что показывает, обычными ручками: так не приходится
повторять на клиенте правила видимости, а гонка «старое пришло позже
нового» невозможна. Публиковать только **после `commit()`** — иначе вкладка
успеет перечитать до фиксации. Адресатов считает `services/live.py`.
Redis недоступен — приложение работает, просто без живых обновлений.
Ручку нельзя буферизовать: в nginx для неё отдельный `location` с
`proxy_buffering off`.

**Скелетоны — только когда показывать нечего.** Раньше при каждой смене
периода список подменялся скелетонами и анимировался дважды: сначала они,
потом строки. Теперь у данных есть метка периода (`loadedKey`), пока она
не совпала — числа в фильтрах не пересчитываются (иначе мелькает значение
от прошлой вкладки), а старые строки остаются на месте, если попадают
в новый период. Снимок уходящего экрана (`.ghost`) анимаций не проигрывает
(`animation: none`), а въезжающий экран получает класс `quiet` — внутри
него каскад строк отключён, движение одно.

**Аватарка — буквы плюс `<img>` сверху.** Фоновая картинка молча
оставляла пустой кружок, когда ссылка Telegram протухала или человека
завели из чата без фото. `components/Avatar.tsx` рисует инициалы всегда,
а фото кладёт поверх и убирает по `onError`.

**Ширина колонки — переменная `--app-w`, а не число.** На широком окне она
растёт до 560 px, и от неё же считаются шторки и кнопка «+». Правки ширины
делать только в ней. Подсветка под курсором живёт в `@media (hover:hover)` —
иначе на сенсорном экране она залипает после касания.

## Правила работы, о которых просил автор

- Не говорить «готово», пока правки не собраны и не закоммичены. Дважды
  случалось, что на устройство ехала старая сборка, а изменения оставались
  в рабочей копии. В интерфейс добавлен видимый штамп сборки (`__BUILD__`)
  и `no-store` на `index.html` — по ним видно, свежая ли версия приехала.
- Убирать за собой `.git/index.lock` после git-команд из песочницы —
  иначе у автора не выполняется `git add`.
- Комментарии в коде — по-русски, объясняют «почему», а не «что».

## Состояние на 14 августа 2026

Сделано: отмена мероприятия, приглашение в группу с ответом принять/отказаться,
удаление участника организатором, сокрытие уже приглашённых в подборе людей,
скелетоны и каскадное появление списков, inline-кнопки «Иду / Под вопросом /
Не иду» в уведомлении Telegram.

Свежее: экраны обновляются сами — ответил участник, и организатор видит это
в «Кто идёт» без перезагрузки (SSE + Redis). Мероприятие можно растянуть на
несколько дней кнопкой «свой выбор» в длительности, у кворума появился срок
с датой (по умолчанию — за сутки до начала). Плюс починены дёрганые
переходы между вкладками, пропадающие аватарки и прыгающие счётчики
фильтров.

Раньше: бота можно добавить в чат Telegram — заводится группа с названием
чата, владелец чата становится владельцем группы, состав пополняется кнопкой
«Я в деле», а мероприятия этой группы анонсируются в самом чате. Чат
переименовали — переименовалась группа, вышел из чата — вышел из группы,
убрали бота — группа удалена (вернут — поднимется вместе с мероприятиями).

Раньше: исключённого можно вернуть — и на мероприятие, и в группу. Он остаётся
блоком «Убраны» / «Исключены» с кнопкой «Вернуть», попадает в контакты, чтобы
не пропасть из подбора людей, а повторное приглашение больше не падает на
`dedup_key`. Плюс работа мышью и клавиатурой: колонка шире на большом окне,
шторки становятся окнами по центру, Esc закрывает верхнюю из них, стрелки
листают период, Home возвращает на сегодня.

Не сделано и обсуждалось: чат группы и мероприятия (есть в SPEC.md, в коде
нет), Alembic вместо `migrate.py`, экран выбора часового пояса в профиле.
Автору стоит убрать `DEV_LOGIN_TOKEN` из `.env` на сервере — он добавлялся
только для отладки.
